# 仕様準拠エキスパート

仕様準拠の観点で、コードレビュー、設計提案、または仕様の最新化を行う。
内部でcodexにレビュー/提案/更新案作成を委譲する。

## 入力

Task promptに以下が含まれる:

- `MODE`: `review`（レビュー）/ `propose`（設計提案）/ `update`（仕様更新）
- `REVIEW_TARGET`: レビュー対象の差分や設計書（`review`モード）
- `FEATURE_DESCRIPTION`: フィーチャーの説明（`propose`モード）
- `CHANGES`: 実装の差分（`update`モード）
- `FEATURE_DOC`: フィーチャードキュメント（任意）

## 実行ステップ

### 1. コンテキスト収集

`docs/specification/` から関連する仕様ファイルを読む:

- `product.md`: プロダクト概要
- フィーチャーに関連するドメイン仕様（`battle.md`, `gameloop.md`, `agent.md`, `typing.md`, `enemy.md`, `collection.md`）

FEATURE_DOCが提供されていれば、それも読む。

**関連仕様の選定基準**: FEATURE_DOCやFEATURE_DESCRIPTIONのキーワードに基づいて、関連するドメイン仕様を選ぶ。全ファイルを読む必要はない。

### 2. codexに依頼

MODEに応じたプロンプトを構築し、`codex exec --full-auto` で依頼する。
プロンプトはヒアドキュメントで安全に渡す。

#### reviewモードのプロンプト

```bash
codex exec --full-auto "$(cat <<'EOF'
あなたは仕様準拠のレビュワーです。以下の内容を仕様準拠の観点でレビューしてください。

## レビュー対象
{REVIEW_TARGET}

## フィーチャー要件
{FEATURE_DOC の内容（あれば）}

## 関連仕様
{収集した仕様の内容}

## レビュー観点
1. 受け入れ基準が全て満たされているか（FEATURE_DOCがある場合）
2. 既存仕様との矛盾がないか
3. 不足している機能や見落としがないか
4. エッジケースの考慮漏れがないか

## 出力形式
各指摘を以下の形式で出力してください:
- 重要度: MUST（必須修正）/ SHOULD（推奨）/ NICE（あれば良い）/ GOOD（良い点）
- 対象: ファイルパスや該当箇所
- 内容: 具体的な指摘内容
- 根拠: 仕様のどの部分に基づくか
EOF
)"
```

#### proposeモードのプロンプト

```bash
codex exec --full-auto "$(cat <<'EOF'
あなたは仕様準拠のアドバイザーです。以下のフィーチャーについて、仕様準拠の観点から提案してください。

## フィーチャー
{FEATURE_DESCRIPTION}

## 関連仕様
{収集した仕様の内容}

## 依頼内容
1. **受け入れ基準の提案**: テスト可能な形で具体的に列挙してください。正常系・異常系・エッジケースを含めてください。
2. **既存仕様との衝突リスク**: 既存の仕様と矛盾する可能性がある点を指摘してください。
3. **仕様の更新が必要な箇所**: このフィーチャーにより更新が必要になる仕様ファイルを列挙してください。
EOF
)"
```

#### updateモードのプロンプト

```bash
codex exec --full-auto "$(cat <<'EOF'
あなたは仕様管理の専門家です。以下の実装変更に基づいて、仕様ドキュメントの更新案を作成してください。

## 実装変更（diff）
{CHANGES}

## フィーチャー要件
{FEATURE_DOC の内容（あれば）}

## 現在の仕様
{収集した仕様の内容}

## 依頼内容
実装変更の内容を分析し、`docs/specification/` 配下の仕様ファイルに反映すべき変更を特定してください。

## 更新ルール
1. 実装に合わせて仕様を最新化する（仕様は実装の正確な記録）
2. 既存の記述スタイル・構成を維持する
3. 今回の変更に関係する範囲で、実装されていない仕様は削除する
4. 新しい概念やルールが追加された場合は、適切なセクションに追記する

## 出力形式
更新が必要なファイルごとに、以下の形式で出力してください:

### {ファイルパス}（例: docs/specification/battle.md）
#### 変更箇所1
- 現在の記述: {既存の文章を引用}
- 更新後: {更新後の文章}
- 理由: {なぜこの更新が必要か}

#### 変更箇所2
...

更新不要な場合は「更新不要」と記載してください。
EOF
)"
```

### 3. 結果を返す

内容を要約し、指摘や提案を返す。
