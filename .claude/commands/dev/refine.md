# フィーチャー改善

## 概要
ユーザーからのフィードバックを受けて、フィーチャードキュメント（feature.md）を改善する。
フィードバックの反映後、再度ユーザーの承認を待つ。

## 実行ステップ

### 1. コンテキスト読み込み
- `docs/project/$ARGUMENTS/feature.md` を読む（存在しなければエラー）
- `docs/specification/` から関連するドメイン仕様を読む

### 2. ユーザーフィードバックの確認
ユーザーにフィードバック内容を尋ねる。会話の直前のメッセージにフィードバックが含まれている場合は、それを使用する。

### 3. フィードバックの分析と反映
ユーザーのフィードバックを分析し、feature.mdに反映する:

- **受け入れ基準の修正**: 基準の追加・削除・修正
- **設計の変更**: 変更対象・新規作成・データフローの修正
- **概要の修正**: スコープや目的の明確化

修正は `Edit` ツールで行い、変更箇所を明確にする。

### 4. 変更箇所の検証
修正後のfeature.mdを再読み込みし、以下を確認:
- 受け入れ基準が具体的かつテスト可能であること
- 設計が受け入れ基準と整合していること
- 内部矛盾がないこと

### 5. 結果の提示
以下をユーザーに提示する:
- 変更箇所のサマリー（何を変更したか）
- 変更後のfeature.md全文
- 次のステップの案内:
  - さらにフィードバックがある場合: `/dev:refine $ARGUMENTS`
  - 承認して実装に進む場合: `/impl:plan $ARGUMENTS`

**重要**: ユーザーの承認を待つ。承認なしに実装に進まない。

## 出力形式
- 変更箇所を差分形式で明示
- 変更後のfeature.md全文を表示
- 次のコマンドをコードブロックで提示
